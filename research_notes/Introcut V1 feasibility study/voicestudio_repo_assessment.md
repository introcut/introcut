# VoiceStudio (debpalash/VoiceStudio) repository assessment for Introcut V1, as of 2026-10-22

Method note: facts below come from the GitHub API, raw repo files (I also shallow-cloned `main` on 2026-10-22 and grepped it; paths are given as GitHub links), Hugging Face model cards, the OmniVoice paper (arXiv 2604.00688) and a few secondary sources. Where a licence text could not be read, it is marked "verify". I am not a lawyer; licence/legal remarks are engineering readings, not legal advice.

## 1. What is the repo, how healthy is it, and are the "fully local" and "646 languages" claims supported?

### Takeaway
VoiceStudio is a very active, young (created 2026-04-09), AGPL-3.0, Electron + Python-backend desktop app whose default engine is the third-party model OmniVoice (k2-fsa), whose weights are non-commercial. "646 languages" is supported only as "the OmniVoice training catalogue lists 646 languages" (many with 4-10 h of data), not as proven quality per language. "Fully local" is largely true for the default path, with optional cloud features.

## 2. Architecture, stack, models and their licences (and Hindi/Nepali quality)

### Takeaway
Electron UI + managed Python (FastAPI) backend; default TTS/cloning engine is OmniVoice (0.6B Qwen3-based diffusion-LM TTS) whose weights are CC-BY-NC and whose audio tokenizer carries the Boson Higgs Audio 2 Community License on top of Llama 3 terms. Other engines are optional. Hindi and Nepali are both in OmniVoice, with paper-reported intelligibility numbers that look good but are self-built benchmarks measured by ASR.

### Cited Findings
- Stack: Electron (only desktop shell since 0.5.3), Python >=3.11 FastAPI backend, React frontend, bun/turbo monorepo, SQLite + alembic, torch 2.8, transformers >=5.10, gradio — [README](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/README.md), [pyproject](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/pyproject.toml). Dependencies include whisperx, faster-whisper, pyannote-audio, demucs, audioseal, pedalboard, sherpa-onnx, kittentts, argostranslate, yt-dlp; Apple-only mlx-whisper / mlx-audio / parakeet-mlx — same pyproject.
- Application licence: "free and open-source software, licensed under the GNU Affero General Public License, Version 3" (AGPL-3.0-only; LICENSE is the stock AGPL text with no added terms). "Modified versions offered over a network must also offer their source code" — [LICENSE-NOTICE.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/LICENSE-NOTICE.md), [LICENSE](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/LICENSE).
- Model licence statement by the repo itself: "Model weights, tokenizers, and other third-party assets retain their own terms"; the default k2-fsa/OmniVoice card lists code as Apache-2.0 and "pretrained weights as CC-BY-NC"; `audio_tokenizer/LICENSE` has Boson Higgs Audio 2 and Meta Llama community terms; "no commercial clearance is asserted by the initial inventory"; "no production model currently has the complete evidence needed" — [LICENSE-NOTICE.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/LICENSE-NOTICE.md), [model-inventory.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/licensing/model-inventory.md).
- OmniVoice (default engine): HF card says code Apache 2.0, model CC-BY-NC "due to constraints from its training data (e.g., Emilia)"; 0.6B params, base Qwen/Qwen3-0.6B-Base, 24 kHz output, zero-shot cloning from a short reference, voice design by attributes, RTF 0.025 (about 40x real time) — on GPU (paper: single H100, fp16) — [HF k2-fsa/OmniVoice](https://huggingface.co/k2-fsa/OmniVoice), [OmniVoice README](https://github.com/k2-fsa/OmniVoice). The paper counts 0.8B parameters including tokenizer/vocoder, uses the Higgs Audio tokenizer (8 codebooks) and 581k h from 50 open datasets (Emilia, Common Voice, FLEURS, LibriTTS…) — [arXiv HTML 2604.00688v3](https://arxiv.org/html/2604.00688v3).
- Higgs tokenizer licence ("BOSON HIGGS AUDIO 2 COMMUNITY LICENSE AGREEMENT", built on Meta Llama 3 Community License): an expanded licence is needed above "100,000 annual active users in the preceding calendar year"; required display "Built with Higgs Materials licensed from Boson AI USA, Inc."; must follow the Llama Acceptable Use Policy; materials may not be used to improve another LLM — [OmniVoice audio_tokenizer/LICENSE](https://huggingface.co/k2-fsa/OmniVoice/raw/main/audio_tokenizer/LICENSE). Conflict: the third-party GGUF card says the codec is "Apache 2.0" — [Serveurperso/OmniVoice-GGUF](https://huggingface.co/Serveurperso/OmniVoice-GGUF); the k2-fsa-bundled LICENSE file above is the primary source, and VoiceStudio's own inventory also records "Higgs Audio 2; Meta Llama 3".
- Repo's licence flags: all four inspected-noncommercial records are OmniVoice, OmniVoice-GGUF (CC-BY-NC-4.0), `facebook/nllb-200-distilled-600M` (CC-BY-NC-4.0, used for translation) and Llama-OuteTTS (CC-BY-NC-SA-4.0 + Llama-3.2). Whisper large-v3 family labelled mit/apache-2.0 (unreviewed), VoxCPM2 apache-2.0, CosyVoice3-0.5B apache-2.0, MOSS-TTS-Nano-100M "apache-2.0" metadata but card says do not treat as licensed until a root LICENSE appears, IndexTTS-2.5 "other" with a separate written licence above user/revenue thresholds — [model_licenses.json](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/backend/config/model_licenses.json) (first 100k chars only).
- Engine catalogue (17 TTS engines incl. OmniVoice, VoxCPM2, MOSS-TTS-Nano, KittenTTS, CosyVoice 3, GPT-SoVITS, IndexTTS 2.5, Supertonic-3, PocketTTS, audio.cpp/Breeze-TTS-2; 11 STT engines incl. WhisperX, faster-whisper, Parakeet, SenseVoice). Docs give no Hindi/Nepali support statement per engine; audio.cpp weights are "research/non-commercial", Supertonic-3 and PocketTTS "need a license" — [docs/engines/README.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/engines/README.md).
- Watermark model: AudioSeal (Meta), invisible watermark, on by default (`watermark.invisible` default True); visible video logo overlay default True — [services/watermark.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/services/watermark.py). AudioSeal HF card: licence MIT; README says full MIT including weights since 2024-04-02 — [HF facebook/audioseal](https://huggingface.co/facebook/audioseal), [search summary of AudioSeal README](https://raw.githubusercontent.com/facebookresearch/audioseal/main/README.md).
- Translation for dubbing: LLM providers (user key) or local Argos Translate; NLLB-200 option is CC-BY-NC; Nepali NLLB bug (code `ne` vs `npi_Deva`) closed 2026-10-07 — [issue #2624](https://github.com/debpalash/VoiceStudio/issues/2624).
- Hindi in OmniVoice: catalogue row "Hindi | hi | hin | 117.17" h; "Nepali | npi | npi | 171.5" h (Nepali's ID in the app is `npi`, not `ne`) — [docs/languages.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/languages.md). Paper: Hindi 4.33% WER, 0.863 SIM-o on MiniMax-Multilingual-24 (MiniMax 6.96%, ElevenLabs 5.83%); FLEURS CER Hindi 2.64 vs ground truth 2.54; Nepali FLEURS CER 3.43 vs ground truth 4.76; model cards of HF/README do not name Hindi or Nepali — [arXiv HTML](https://arxiv.org/html/2604.00688v3), [HF card](https://huggingface.co/k2-fsa/OmniVoice).
- Voice design is trained "only on Chinese and English data" (OmniVoice README), so "design a Hindi/Nepali voice by description" is not evidenced — [OmniVoice README](https://github.com/k2-fsa/OmniVoice).
- Whisper large-v3 (ASR for transcript/ref text) is used for cloning transcripts — [docs/engines/omnivoice.md](https://github.com/debpalash/VoiceStudio/blob/main/docs/engines/omnivoice.md).

### Inferences
- The default engine is the weak point for Introcut: CC-BY-NC weights + Higgs/Llama licence layers mean VoiceStudio's default pipeline cannot be treated as "permissive". Its own authors say no commercial clearance exists.
- WER/CER figures are ASR round-trip intelligibility on benchmarks built by the authors (the FLEURS-102 set is "self-built"); they say nothing about naturalness, accent or Nepali/Hindi listener preference, and speaker similarity (SIM-o) is a model metric. Treat Hindi/Nepali as "promising, needs a 10-minute listening test by a native speaker".
- Non-OmniVoice engines relevant to Hindi/Nepali cannot be assessed from this repo's docs (gap).

### Gaps
- No per-engine Hindi/Nepali statement in VoiceStudio docs; did not open each engine model card (VoxCPM2, CosyVoice3, MOSS, IndexTTS, Breeze-TTS-2).
- Full licence-record JSON beyond the first 100k characters not read (Argos Translate, Demucs, pyannote records unverified). pyannote-audio models are gated on HF in general (verify).
- No listening-quality evidence for Hindi/Nepali from third parties.

## 3. Hardware, performance, Windows support and install friction

### Takeaway
Windows x64 installer exists and the app bootstraps its own Python; CPU-only works but the default OmniVoice engine is slow there, and users on 4-6 GB GPUs report timeouts. A shy beginner on an average laptop would hit friction (about 10 GB of disk, minutes-long first-run, unsigned installer).

### Cited Findings
- Windows requirements: Windows 10/11 x64 (ARM experimental); "~10 GB free disk for the app, its Python environment, and model weights"; NVIDIA GPU optional; "Python, FFmpeg, and model weights are bootstrapped by the app itself on first launch". Without NVIDIA: CPU PyTorch, about 5 GiB; integrated graphics are not used for AI; docs recommend light engines (KittenTTS, Supertonic-3, PocketTTS) on CPU — [docs/install/windows.md](https://github.com/debpalash/VoiceStudio/blob/main/docs/install/windows.md).
- Windows GPU acceleration is NVIDIA/CUDA only; AMD ROCm on Windows is an open, unvalidated PR (#3045) and Vulkan builds an open PR (#3042) — [docs/performance.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/performance.md), [PR search results](https://api.github.com/search/issues?q=repo:debpalash/VoiceStudio+Windows+CPU+slow&per_page=15).
- OmniVoice: "Recommended VRAM floor: 6 GB"; on 4 GB cards "a render that should take seconds runs for minutes until the compute budget kills it" — [docs/engines/omnivoice.md](https://github.com/debpalash/VoiceStudio/blob/main/docs/engines/omnivoice.md). 32 GB RAM suggested to keep several engines warm — [docs/performance.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/performance.md).
- CPU speed: "CPU is about 2x slower than MPS and more against CUDA... often 10-50x slower than on a GPU"; default CPU budget 4 s per input character (a 400-character passage gets about 1,600 s); no measured CPU RTF given; `docs/benchmarks.md` table is empty ("none yet — contribute yours below") — [docs/performance.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/performance.md), [docs/benchmarks.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/benchmarks.md).
- Field reports (issues): Windows CPU-only 15.6 GB RAM, generation aborted after about 10 min (#2159, v0.5.2); Windows RTX 3060 Laptop 6 GB, three attempts each aborted after about 10 min (#2231, v0.5.3); RTX 4060 audiobook chapter abandoned after 576 s of compute (#2287, v0.5.5); Windows 10 CPU backend died during a 2.45 GB model download (#2079); CPU-only Linux server: a roughly 600-character chunk took 95-280 s (PR #2955); AMD RX 6800 XT fell back to CPU at about 17x slower than real time on IndexTTS (PR #2423) — [GitHub issue/PR search](https://api.github.com/search/issues?q=repo:debpalash/VoiceStudio+Windows+CPU+slow&per_page=15). Several were closed "not planned". Some were fixed in later versions (PR #2500 float32 on CPU, "previously very slow"; PR #2499 longer probe timeouts), so older numbers may overstate current slowness.
- OmniVoice GGUF (quantised, community port): Q8_0 656 MB base + 289 MB tokenizer, Q4_K_M 407 + 252 MB; CUDA/Vulkan/Metal/CPU; weights CC-BY-NC-4.0; Windows support not explicitly stated; "not in installers yet" per VoiceStudio — [HF OmniVoice-GGUF](https://huggingface.co/Serveurperso/OmniVoice-GGUF), [docs/engines/README.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/engines/README.md). A community ONNX conversion exists (Emerald7664/OmniVoice-Onnx); no evidence it runs in-browser — [HF](https://huggingface.co/Emerald7664/OmniVoice-Onnx).
- Voice-clone reference: 3-10 s is "the sweet spot"; with a supplied transcript limited to 20 s; transcript auto-generated via Whisper if absent — [docs/engines/omnivoice.md](https://github.com/debpalash/VoiceStudio/blob/main/docs/engines/omnivoice.md).
- Install friction items: unsigned/ad-hoc signed installer (Windows SmartScreen warning is expected, my inference), one-line `irm https://voicestudio.sh/install | iex` installer — [v0.5.6 notes](https://api.github.com/repos/debpalash/VoiceStudio/releases), [README](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/README.md).

### Inferences
- On the owner's likely hardware (a Lenovo laptop, GPU unknown), a 30-second narration at CPU speeds (even at a conservative 10-50x slower than the GPU's 0.025 RTF, i.e. RTF about 0.25-1.25, plus model load) could take from tens of seconds to minutes if the numbers hold, but real CPU numbers for OmniVoice are not documented and field reports suggest worse; this must be measured (see experiment).
- A "shy beginner" target user is not well served by a 10 GB multi-step install; fine for a creator-tier companion, not for default V1.

### Gaps
- No measured CPU RTF for OmniVoice on a typical laptop; benchmark table empty.
- No documented DirectML path (voicebox lists DirectML, VoiceStudio does not).

## 4. Integration options for Introcut (licence and engineering consequences)

### Takeaway
Only option 1 (separate local server over localhost, user-installed) or option 4 (recommend as companion) are licence-clean for an MIT Introcut; embedding/vendoring VoiceStudio code is not (AGPL), and calling the same OmniVoice weights ourselves fails the "permissive models only" rule. Option 1 is technically feasible but needs the user to whitelist Introcut's origin.

### Cited Findings
- Local API: base `http://127.0.0.1:3900`, loopback needs no credential; OpenAI-compatible `POST /v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/audio/translations`, `GET /v1/models`, `/v1/audio/voices`; native `POST /generate` (multipart: text, language, ref_audio, ref_text, profile_id, engine, stream...) returning audio with metadata headers; MCP at `/mcp`; Scalar docs at `/docs` with an OpenAPI schema — [docs/speech-platform.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/speech-platform.md), [openai_compat.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/api/routers/openai_compat.py), [generation.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/api/routers/generation.py), [main.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/main.py).
- CORS: `allow_origins` defaults to the app's own `localhost`/`127.0.0.1` UI port plus desktop origins; configurable via `OMNIVOICE_ALLOWED_ORIGINS`. A `BrowserGuardMiddleware` "refuses state-changing requests and WebSocket handshakes that another website's page sends, and requests that address this backend by an unrecognized host name (DNS rebinding)". So a page at an Introcut origin cannot POST to it unless the user sets that env var — [csrf.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/core/csrf.py), [main.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/main.py). (Whether `https://introcut.app` or a localhost dev origin gets through after setting the variable is untested: verify.)
- AGPL-3.0: network-served modified versions must offer source. Per the repo's own competitive analysis, its authors treat third-party AGPL/GPL code as "study-only" for their commercial dual licence — [docs/competitive-analysis.md](https://github.com/debpalash/VoiceStudio/blob/main/docs/competitive-analysis.md). The mirror-image applies to Introcut: copying VoiceStudio code into an MIT repo would force AGPL on the combined work (standard copyleft reading; verify with counsel).
- The bundled `omnivoice/` package is separately Apache-2.0 "by its upstream authors and is not relicensed by VoiceStudio" — [LICENSE-NOTICE.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/LICENSE-NOTICE.md). The upstream OmniVoice code is Apache-2.0 — [k2-fsa/OmniVoice](https://github.com/k2-fsa/OmniVoice).
- Contributing upstream requires signing a CLA assigning rights to the company (licence to Yupcha Softwares Private Limited, not copyright transfer) — [CLA-1.0.md](https://github.com/debpalash/VoiceStudio/blob/main/.github/CLA-1.0.md).

| Option | What it means | Effort | Licence consequence | Key risks | User experience |
|---|---|---|---|---|---|
| 1. Localhost companion server | Introcut (web PWA) calls `127.0.0.1:3900` `/generate` or `/v1/audio/speech` | About 1-3 days for a provider adapter, plus consent UI and fallback | OK for MIT Introcut as a separate process the user installs (we ship no AGPL code; verify with counsel). Weights remain the user's NC-licensed download | User must install a 214 MB app plus about 10 GB, whitelist our origin via env var, Chrome local-network prompts and mixed-content rules (verify); API churn (0.x); CC-BY-NC means users should not monetise output (see section 5) | Power-user flow: install companion, paste nothing, click "Use local voice"; shy beginner will struggle |
| 2. Embed / vendor code | Copy Python/Electron code into Introcut or a Windows build | Large | Incompatible with MIT repo; whole build becomes AGPL | Violates Introcut hard rule (MIT/Apache only) | n/a |
| 2b. Vendor only upstream `omnivoice` (Apache-2.0) in a Windows desktop sidecar | Use Apache code, not VoiceStudio | Medium-large (Python packaging) | Code OK; weights CC-BY-NC fail the rule | Still non-permissive weights | Same as above |
| 3. Borrow model list, call models ourselves | e.g. run OmniVoice, VoxCPM2, CosyVoice3 via our own runtime | Large (Python or ONNX) | OmniVoice weights NC + Higgs/Llama terms: not allowed to bundle. VoxCPM2 Apache-2.0 and CosyVoice3-0.5B Apache-2.0 are "unreviewed" by VoiceStudio itself; verify each card, Hindi/Nepali support unknown | Reproduces the model-licensing work the earlier research said is hard | Possible later in a Windows desktop sidecar |
| 4. Recommend as optional companion | Docs link: "if you want a local voice, install X; Introcut imports the WAV" | Hours (docs + file import) | No licence entanglement | NC weights still bind the user; no direct integration | Manual: user makes WAV elsewhere, imports; works today |
| 5. Do not use | Skip | 0 | n/a | Lose a broad-language local option | n/a |

### Inferences
- If Introcut's own rule is "bundled things must be permissive", VoiceStudio can only ever be a user-installed external tool. The cleanest, lowest-risk interop is file import of the user's WAV (option 4), with an optional localhost adapter as an advanced feature.
- For a free hobby tool the NC clause may be tolerable for private use; for creators who monetise Shorts it is a trap (see section 5), so Introcut should not make OmniVoice output the default path.

### Gaps
- Did not test whether CORS actually admits a browser PWA after setting `OMNIVOICE_ALLOWED_ORIGINS`, nor Chrome's Local Network Access permission behaviour from an HTTPS origin to `127.0.0.1` (verify in the experiment).
- Endpoint schemas for `/generate` returning only 24 kHz WAV: not tested.

## 5. Voice-cloning safety in the repo, what Introcut must add, and legal context

### Takeaway
VoiceStudio has a partial consent mechanism (a recorded "consent lock") and a default-on invisible AudioSeal watermark, but plain local synthesis never requires consent. Introcut must own its consent, labelling and own-voice-only logic rather than relying on VoiceStudio.

### Cited Findings
- Consent lock: a voice profile becomes `verified_own_voice` when the owner records a consent statement; "the recording is provenance, not a voiceprint check — agentic features and gallery sharing gate on the flag; plain local synthesis never does" — [profiles.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/api/routers/profiles.py) (consent endpoint `POST /profiles/{id}/consent`), [migration 0003](https://github.com/debpalash/VoiceStudio/blob/main/backend/migrations/versions/0003_voice_profile_consent.py).
- The repo's licence notice says its reviewed-file workflow "does not ... verify voice consent or add a waiver" — [LICENSE-NOTICE.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/LICENSE-NOTICE.md).
- Watermark: AudioSeal invisible watermark default on ("No audio producer bypasses `mark_synthetic`" per privacy doc), user can turn it off in Settings > Privacy; if the generator fails to load, "generation continues without an invisible watermark"; there is a `/watermark/detect` endpoint; visible video logo overlay default True, visible audio tone default off — [docs/electron-privacy.md](https://github.com/debpalash/VoiceStudio/blob/main/docs/electron-privacy.md), [watermark.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/api/routers/watermark.py), [services/watermark.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/services/watermark.py). The README itself does not mention watermarks.
- README: "Clone voices only with permission." OmniVoice disclaimer prohibits "unauthorized voice cloning, voice impersonation, fraud, scams" and disclaims liability — [README](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/README.md), [k2-fsa/OmniVoice](https://github.com/k2-fsa/OmniVoice).
- The reference voice can be any uploaded audio (`ref_audio` form field on `/generate`) — [generation.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/api/routers/generation.py). So the consent recording is not technically bound to the cloned voice (no speaker-verification between consent clip and reference).
- Chatterbox (alternative) watermarks every output with PerTh: "imperceptible neural watermarks that survive MP3 compression" — [HF ResembleAI/chatterbox](https://huggingface.co/ResembleAI/chatterbox).
- India: IT Rules amendment on "synthetically generated information", notified 2026-02-10, effective 2026-02-20; platforms/tools that enable creation must label synthetic content prominently and add persistent metadata where feasible; a further April 2026 draft would require labels visible for the whole duration (not confirmed final) — [IPleaders](https://blog.ipleaders.in/it-rules-2026/), [Hogan Lovells](https://www.hoganlovells.com/en/publications/india-introduces-mandatory-labelling-for-ai-and-3hour-takedown-for-illegal-content), [Mondaq/S.S. Rana](https://www.mondaq.com/india/new-technology/1801930/india-tightens-oversight-on-ai-generated-content-under-it-rules). Secondary sources only; official gazette not read.
- EU: AI Act Art. 50 deepfake-labelling duty applies since 2026-08-02; machine-readable marking duty for systems already on the market delayed to 2026-12-02 by the Digital Omnibus — [Ropes & Gray](https://www.ropesgray.com/en/insights/viewpoints/2026/08/102nfqm/you-talkin-to-me-operationalising-the-eu-ai-acts-transparency-obligations), [CSA note](https://labs.cloudsecurityalliance.org/wp-content/uploads/2026/07/CSA_research_note_eu_ai_act_article_50_transparency_20260729-csa-styled-1.pdf); sources disagree on exact Omnibus publication status.
- The repo's own analysis cites Tennessee's ELVIS Act as reaching "tool providers" and treats consent gates as a "legal floor" — [competitive-analysis.md](https://github.com/debpalash/VoiceStudio/blob/main/docs/competitive-analysis.md).

### Inferences
- To meet Introcut's rules, Introcut must itself (a) record a spoken consent phrase on the same device and session as the reference sample, store it with the project, and ideally check that the consent clip and the reference share the same speaker (a similarity check), (b) only accept microphone-recorded samples (not arbitrary uploads) for cloning, (c) show an "AI-generated" label at export and embed a label in the exported MP4 metadata (supports India persistent-metadata and EU Art. 50 direction), (d) never disable or strip watermarks (do not recommend turning VoiceStudio's AudioSeal off), (e) show the user an on-screen notice that the companion's model weights are non-commercial.
- Avatar: no avatar capability exists here, and a photo-based avatar for the user's own face needs its own consent step; nothing in VoiceStudio helps.

### Gaps
- Nepal law: I did not research it (no sourced statement; mark "verify" if the report writer needs it). Platform policies (YouTube/Instagram AI-labelling) not researched.
- I did not read the official Indian gazette text or EU regulation text.

## 7. Verdict and first experiment

### Takeaway
Verdict: "inspiration only plus optional companion later". Not usable as a bundled/default V1 component (AGPL app, CC-BY-NC default weights, heavy install, no avatar). Usable now only as a user-installed external tool whose output Introcut imports; a localhost adapter is "usable later" after a measured experiment. It also confirms OmniVoice as a candidate for evaluating Hindi/Nepali cloning quality privately.

### Cited Findings
- Reasons rest on the cited items above: AGPL-3.0 app and "no commercial clearance is asserted" for models ([LICENSE-NOTICE.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/LICENSE-NOTICE.md)); OmniVoice weights CC-BY-NC ([HF](https://huggingface.co/k2-fsa/OmniVoice)); Higgs/Llama licence layers ([LICENSE](https://huggingface.co/k2-fsa/OmniVoice/raw/main/audio_tokenizer/LICENSE)); about 10 GB install and CPU slowness ([windows.md](https://github.com/debpalash/VoiceStudio/blob/main/docs/install/windows.md), [performance.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/performance.md)); consent is optional locally ([profiles.py](https://github.com/debpalash/VoiceStudio/blob/main/backend/api/routers/profiles.py)).
- Positives worth borrowing: its consent-lock data model, default-on AudioSeal watermark (MIT code and weights), a speech-platform with OpenAI-style routes, and the per-language training-hours table as a way to set quality expectations ([languages.md](https://raw.githubusercontent.com/debpalash/VoiceStudio/main/docs/languages.md)).

### Inferences
- First experiment (under 60 minutes, private testing only, own voice only):
  1. Download `VoiceStudio-Electron-0.5.6-win-x64.exe` (or the current release) from the releases page, compare SHA-256 with `SHA256SUMS.txt`, install, let it bootstrap; note disk used and minutes to first generation.
  2. In Clone, record a 5-10 s sample of your own voice (read English), record the consent statement, and generate a Hindi sentence and a Nepali sentence (set language to Hindi/`hi` and Nepali/`npi`). Have a native speaker rate pronunciation and voice likeness. Record the generation time for 10 s of audio (that is your real CPU or GPU RTF).
  3. Set `OMNIVOICE_ALLOWED_ORIGINS` to include `http://localhost:5173` (Introcut dev server), restart, then from the Introcut dev page run a `fetch('http://127.0.0.1:3900/v1/audio/speech', ...)` test to see whether CORS, mixed-content and Chrome's local-network prompt allow it. Also run `GET /.well-known/voicestudio-speech`.
  4. Optionally repeat step 2 in voicebox with Chatterbox Multilingual (Hindi) to compare quality and install effort.
  Pass criteria: Hindi and Nepali sound intelligible to a native speaker, RTF under about 1 on the owner's laptop, and a browser page can call the API after one setting. If any fail, drop the localhost adapter and keep option 4.

### Gaps
- Not tested by me: install on real Windows hardware, real quality of Hindi/Nepali audio, CORS behaviour from a PWA.
