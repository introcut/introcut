# Programmatic generative video: APIs, hosts, open weights, free compute, terms (as of 2026-10-22)

Research date: 2026-10-22. Method note: many vendor pricing pages could not be fetched directly; where a figure comes from an aggregator/blog it is labelled "secondary". Anything not confirmed on a primary page is marked "verify". Model cards for CogVideoX / Mochi / HunyuanVideo / Wan 2.2 date from 2024-2025 and are therefore more than 3 months old (flagged). The ecosystem in these sources moves very fast (Veo 3.1 was scheduled to shut down on the very day of this research), so re-check every number before the owner commits to anything.

## 1. Official APIs: models, price per second, free tier, limits, 9:16, audio, SDK

### Takeaway
Google is mid-migration: the Veo 3.1 preview models have a documented shutdown date of 2026-10-22 and the replacement is `gemini-omni-1.1-flash` (about $0.10/s at 720p, paid tier only, no free tier, 9:16 supported, audio on by default, async file-polling). Sora's API is gone (shut down 2026-09-24). Most other vendors price 720p video in the roughly $0.05-$0.15 per second band, so a 30 s story is about $1.50-$5 raw before retries.

### Cited Findings

**Google (Gemini API)**
- Veo 3.1 preview models: Standard `veo-3.1-generate-preview` $0.40/s (720p/1080p), $0.60/s (4K); Fast `veo-3.1-fast-generate-preview` $0.10/s (720p), $0.12/s (1080p), $0.30/s (4K); Lite `veo-3.1-lite-generate-preview` $0.05/s (720p), $0.08/s (1080p), no 4K. Prices include audio. Free tier "not available" for any Veo 3.1 variant. Pricing page dated as fetched 2026-10-22. — [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing)
- The same page marks all three Veo 3.1 models as deprecated, shutting down October 22, 2026, with replacement `gemini-omni-1.1-flash`. — [Gemini API deprecations](https://ai.google.dev/gemini-api/docs/deprecations)
- Replacement `gemini-omni-1.1-flash` (released 2026-08-27, no shutdown date announced): paid tier only; $17.50 per 1M output tokens for video, billed at 5,792 tokens per second of 720p video, which Google states is "about $0.10 per second". — [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing); [deprecations](https://ai.google.dev/gemini-api/docs/deprecations)
- Omni Flash video features: `aspect_ratio` "9:16" for portrait (16:9 default); resolution 360p, 720p (default), 1080p (upscaled), 4k (upscaled); image-to-video, first+last frame interpolation, "subject reference" with multiple images, video references (max 3 clips of up to 3 s each), audio references unsupported; extensions add 3-10 s each, up to 40 s total; audio generated by default (prompt "No dialogue" to avoid speech); all outputs carry SynthID watermark; endpoint is the Interactions API (`/v1beta/interactions`) via SDKs or REST; for videos over 4 MB use `delivery="uri"` then poll the file until state `ACTIVE`, `FAILED` means failure. — [Gemini Omni docs](https://ai.google.dev/gemini-api/docs/omni)

- Because model families churn every few months (Veo 3.1 lifetime Oct 2025 to Oct 2026), a generator-profile abstraction with price/duration/aspect metadata held in data, not code, is justified.

## 2. Aggregators and hosts: prices, free credits, browser/CORS, open models

### Takeaway
fal.ai and Replicate are the main async-job hosts; both support submit/poll/webhook patterns, and fal explicitly says "you can call from the browser" but tells you not to expose the key (server proxy). No source retrieved confirmed CORS behaviour for either, so direct-from-browser calls with a user's own key are plausible but must be tested (verify).

### Cited Findings
- fal.ai per-second list prices (primary): Kling 2.5 Turbo Pro and 2.6 $0.07/s; Kling v3 and O3 $0.14/s; MiniMax H3 Max $0.05/s, H3 Max Turbo $0.025/s; Seedance billed per token (see Q1). The page lists no Veo, Wan or LTX video prices in that table and mentions no free credits policy. — [fal.ai pricing](https://fal.ai/pricing)
- fal FAQ: you can call fal from the browser but "you should not expose your API key in client-side code"; recommends a server-side proxy; requests above your concurrency limit are queued; new accounts start at 2 concurrent requests, rising automatically with credit purchases up to 40; free credits and coupons expire from about 1 week to 1 year depending on grant. CORS not mentioned. — [fal.ai FAQ](https://fal.ai/docs/model-apis/faq)
- Replicate (primary pricing page): wavespeedai/wan-2.1-i2v-480p $0.09/s, wan-2.1-i2v-720p $0.25/s; GPU time per second: T4 $0.000225, L40S $0.000975, A100 80GB $0.0014, H100 $0.001525; the page mentions no free credits. — [Replicate pricing](https://replicate.com/pricing)
- Replicate async model: create a prediction (async by default), supply `webhook` URL with optional `webhook_events_filter` (e.g. `["completed"]`), or poll `urls.get` every 1-2 s until terminal state. CORS, output file retention and rate limits are on other pages not retrieved. — [Replicate create-a-prediction](https://replicate.com/docs/topics/predictions/create-a-prediction)
- Resold Google/Kling/Seedance routes also exist on Runway (Veo 3.1 at $0.10-$0.40/s, see Q1). — [Runway API pricing](https://docs.dev.runwayml.com/guides/pricing/)
- Secondary: a 2026 comparison puts fal.ai at $0.03-$0.10/s for many hosted models and Seedance 2.0 Fast about $0.022/s on one host vs about $0.09/s direct. — [Techsy](https://techsy.io/en/blog/best-ai-video-providers) (secondary, unverified)
- Together, Fireworks, Novita, WaveSpeed: not researched beyond WaveSpeed appearing as the provider of the Replicate Wan 2.1 models above (gap).

### Inferences
- Because every host returns a job ID and a downloadable URL, one `submit -> poll/webhook -> download` interface can cover Gemini, fal, Replicate, Runway, Luma, etc.
- A browser-only app has no public webhook endpoint, so polling is the only option unless the user supplies their own relay.
- Output-file URLs on third-party CDNs may not send CORS headers, which would block `fetch()` of the video bytes in the browser (verify per provider); fallback is user downloads file, or `<video>` element playback plus a manual save.

### Gaps
- CORS behaviour for fal, Replicate, Runway, Luma, Kling, Gemini not verified (needs an actual browser test).
- Free sign-up credits on fal/Replicate not confirmed in current docs.
- Together, Fireworks, Novita pricing and open-model hosting not covered.

## 3. Open-weights video models: licenses, VRAM, speed, can they run on free Colab/Kaggle/ZeroGPU

### Takeaway
Wan 2.2 (July 2025) is the last open Wan release that is confirmed Apache-2.0 from its own model card; its 5B variant runs on a 24 GB consumer GPU (about 9 min for a 5 s 720p clip), so free Colab T4s (16 GB) are marginal. Several 2026 claims (Wan 3.0 open weights, LTX-2.3 Apache) are unverified or conflicting. None of these approaches reach Veo/Kling quality at a 30 s story scale for free.

### Cited Findings
- Wan2.2-TI2V-5B model card: licence Apache 2.0; runs on at least 24 GB VRAM (e.g. RTX 4090) with offloading flags; 720P at 24 fps (1280x704 / 704x1280, so a native portrait size exists); "a 5-second 720P video in under 9 minutes on a single consumer-grade GPU"; license prohibits illegal/harmful uses; authors claim no rights to output. — [Wan2.2-TI2V-5B](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B) (model released July 2025, older than 3 months)
- The Wan-AI HF org lists Wan2.2 variants including T2V-A14B, I2V-A14B, TI2V-5B, S2V-14B, Animate-14B; the listing shows no license info. — [Wan-AI on HF](https://huggingface.co/Wan-AI)
- Secondary: Wan 2.5 was API-only and the open line stops at 2.2; a guide claims A14B can run in about 8 GB with CPU offload and 4-bit GGUF; a July 2026 article calls "Wan 2.7 under Apache 2.0" claims fabricated; wan27.org claims Wan 3.0 open weights (1.3B/14B, Apache-2.0, late April 2026) but its evidence is a LinkedIn post and it sells hosted Wan access. — [howaiworks.ai Wan](https://howaiworks.ai/models/wan); [wan27.org Wan 3.0](https://wan27.org/blog/wan-3-open-source) (conflicting, treat as unverified)
- LTX-Video (older): HF license listed as "other" (LTX-Video Open Weights License files per version); 2B and 13B variants (0.9.x), FP8 versions; claims real-time-ish speed on strong GPUs; no VRAM numbers on the page. — [Lightricks/LTX-Video](https://huggingface.co/Lightricks/LTX-Video)
- LTX-2 (19B, audio+video in one model): "ltx-2-community-license-agreement"; variants dev (bf16), fp8, fp4, distilled (8 steps), upscalers; no VRAM figure; no portrait guidance on the card. Secondary: LTX-2 community license is free for orgs under about $10M revenue; one source claims LTX-2.3 is Apache-2.0 but more sources say Community License. — [Lightricks/LTX-2](https://huggingface.co/Lightricks/LTX-2); [Magic Hour LTX-2.3 vs Wan 2.2](https://magichour.ai/blog/ltx-2-3-vs-wan-2-2) (secondary; verify licence file)
- HunyuanVideo: license "tencent-hunyuan-community" (terms not on the page, commonly known to have territory limits: verify the file); GPU peak 60 GB (720x1280x129f) or 45 GB (544x960x129f); 80 GB recommended. — [tencent/HunyuanVideo](https://huggingface.co/tencent/HunyuanVideo) (2024 model, old)
- Mochi-1 preview: Apache 2.0; about 22 GB in bf16 via Diffusers, 42 GB for best quality, H100 recommended; 480p; about 2.8 s clips. — [genmo/mochi-1-preview](https://huggingface.co/genmo/mochi-1-preview) (2024, old)
- CogVideoX-5b: "CogVideoX license" (custom; read the file); 5 GB+ VRAM with Diffusers optimisations; fixed 720x480, about 6 s at 8 fps; about 180 s on an A100 / 90 s on an H100 for 50 steps. — [CogVideoX-5b](https://huggingface.co/zai-org/CogVideoX-5b) (2024, old; Apache-2.0 applies to the smaller 2b variant per my background knowledge: verify)
- Open-Sora: not researched (gap).
- Quality: secondary comparison only says LTX-2.3 and Wan 2.2 are the two main open models; no objective Veo/Kling comparison retrieved (gap).

### Inferences
- Realistic free option: Wan 2.2 5B (Apache-2.0, portrait-capable) on a 24 GB GPU is the only clearly licensed, reasonable-quality choice; 6 clips at about 5-9 min each is 30-55 min on a 4090, and much slower or impossible on free Colab T4/Kaggle P100/T4 without heavy quantization (verify with an actual test).
- HunyuanVideo, Mochi and CogVideoX are quality/length/resolution-limited and less compatible with a "short vertical story" product.
- Because licences differ (Apache vs Community vs Tencent vs CogVideoX), the app must show each profile's license, per the project's licence rule.

### Gaps
- Official GitHub/HF verification of any Wan 3.0 weights and licence.
- VRAM and exact licence terms for LTX-2/2.3, HunyuanVideo-1.5 or newer open models, Open-Sora.
- Measured throughput on T4/P100/ZeroGPU; Colab/Kaggle fit not tested.

## 4. Free compute for the user's own account (HF, Colab, Kaggle, Flow credits, cloud credits)

### Takeaway
There are no free generative-video API quotas that an open-source browser app can safely orchestrate. Hugging Face ZeroGPU gives signed-in free users only minutes per day; Colab's free tier restricts web-UI/remote-control style content generation; Flow credits do not work with the API; the Google Cloud $300 trial is the one plausible "free" route, via the user's own billing account.

### Cited Findings
- ZeroGPU daily quota: unauthenticated 2 min; free account 5 min; PRO 40 min (extensible); Team 40; Enterprise 60; resets exactly 24 h after first GPU use; PRO can buy extra at $1 per 10 minutes; hardware is NVIDIA RTX Pro 6000 Blackwell (large = half, 48 GB; xlarge = full, 96 GB at 2x quota); default function duration 60 s, extendable via `@spaces.GPU(duration=...)`; ZeroGPU is Gradio-only; free users may host up to 2 ZeroGPU Spaces. — [HF ZeroGPU docs](https://huggingface.co/docs/hub/spaces-zerogpu). Conflict: a search-summary of other pages gave 3.5 min free / 25 min PRO; the official docs fetched directly show 5 / 40.
- Colab FAQ: free runtimes disallow "remote control such as SSH shells, remote desktops," and restrict "bypassing the notebook UI to interact primarily via a web UI" for content generation; all runtimes disallow file hosting/media serving, torrenting, remote proxies, crypto mining, multiple accounts to evade limits, and deepfakes; usage limits are unpublished and fluctuate; free notebooks max 12 h. The FAQ does not directly address driving a notebook from outside by API. — [Colab FAQ](https://research.google.com/colaboratory/faq.html)
- Kaggle: official Terms/doc pages did not return substantive text, so prohibited-use clauses are unverified. Kaggle's CLI/API does support `kernels push` to run a notebook (third-party tools wrap it), historical quota about 30 GPU hours/week (my background knowledge, not verified now). — [Kaggle terms](https://www.kaggle.com/terms) (page content not retrievable); [kaggle kernels CLI reference](https://linuxcommandlibrary.com/man/kaggle-kernels) (secondary)
- Flow credits vs API: a Google AI Developers forum reply says the Google AI Pro subscription is limited to web apps (Flow, Jules, etc.) and does not cover API requests; a user with 500+ Flow credits reported they cannot use them via the API and got no definitive answer. — [Forum: Does Google One AI Pro include API access for Veo 3?](https://discuss.ai.google.dev/t/does-google-one-ai-pro-include-api-access-for-veo-3-or-is-it-limited-to-flow-only/110794); [Forum: credits in Flow but cannot use via API](https://discuss.ai.google.dev/t/have-credits-in-flow-google-labs-but-cannot-use-them-via-api/113064)
- Flow free allowances (secondary, post-Aug 2026 guide): about 50 credits/day for unpaid users, paid plans 200 / 1,000 / 10,000 / 25,000 monthly credits; sources disagree on Pro's amount. — [DIY AI Veo pricing](https://diyai.io/ai-tools/video-generation/google-veo-pricing/) (secondary, verify)
- Google Cloud: new customers get $300 free credit (typically 90 days, non-transferable) usable on Vertex AI including Veo; these are secondary/third-party descriptions of the trial and the Veo claim refers to Veo 3 preview model IDs, so confirm the trial still covers current video models. — [Google Cloud Free Program](https://cloud.google.com/free/?hl=cy); [TechRadar](https://www.techradar.com/computing/artificial-intelligence/this-simple-trick-gets-you-3-months-of-google-gemini-veo-3-for-free-heres-how-you-can-create-the-best-ai-videos-without-dropping-a-dime) (secondary)
- Gemini API's AI Studio is "paid" when linked to a Cloud project with active billing, even if no fee is charged, which changes data-use terms. — [Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms)
- Runway/Luma/Kling startup credit programmes: not researched (gap).

### Inferences
- What Introcut can legitimately orchestrate: calls the user authorises with their own API key (Gemini/Omni on a billing-enabled or trial-credit project, fal, Runway, etc.). The Google Cloud trial credit is the only widely applicable "free" budget; $300 at about $0.10/s is theoretically about 3,000 s of video (about 100 stories), with 90-day expiry and a card required (card requirement is from background knowledge: verify).
- A browser app calling a user's own HF Space via the official Gradio JS client with the user's HF token is a normal API-style use of Hugging Face (verify: HF terms and whether quota is charged to the caller's token), but with a 5-minute daily free quota it yields perhaps one or two clips per day.
- Driving someone's Colab from the outside is not clearly permitted and conflicts with the spirit of the "web UI / remote control" restrictions; do not build it. The user running a notebook themselves, manually, is fine; Introcut can offer a "copy this notebook/prompt" experience.
- Kaggle's official `kernels push` API exists, but a browser app would need the user's Kaggle API token, CORS is unknown, and Terms text was not verified; treat as not supported in V1.

### Gaps
- Kaggle ToS text and current free GPU hours; Kaggle internet-enabled GPU session behaviour.
- HF terms on programmatic Space use and quota attribution when calling via token.
- Whether Gemini API trial credits are definitely accepted for `gemini-omni-1.1-flash`.
- Runway/Luma/Kling credit programmes.

## 5. Do consumer web app terms forbid automation / API use of web UIs?

### Takeaway
Yes for Kling, explicitly; for Google the general terms ban automated access that violates machine-readable rules and reverse engineering, with product-specific (Flow/Labs) terms not retrieved. Introcut should only use official API keys; the manual route is "user does it in the web UI themselves".

### Cited Findings
- Kling AI user policy (last updated 2026-04-21), Section 3.1(h): users may not "use automated scripts to collect information from or otherwise interact with the Services"; 3.1(b): no reverse engineering or derivative works of the Services; 3.1(f): no bypassing "any measures we may use to prevent or restrict access"; 3.1(g): no incorporating the Services into any other program or product; 2.5: account usable only by the holder; 4.5: output must be labelled as generated by Kling AI (in the quoted passage); 4.6: no commercial use of Output without written permission; 4.10: do not remove or alter legal notices. No clause mentions watermark removal explicitly and the document does not mention an API. — [Kling user policy](https://kling.ai/docs/user-policy)
- Google Terms of Service: users must not use "automated means to access content from any of our services in violation of the machine-readable instructions" (e.g. robots.txt); no reverse engineering of services or ML models (except as law allows); for generative AI, no using AI-generated content from the services to develop ML models, no jailbreaking/prompt injection, and no misleading others into thinking generative AI content was created by a human; a "Generative AI Prohibited Use Policy" is referenced but not retrieved. Flow- or Labs-specific additional terms were not found. — [Google Terms of Service](https://policies.google.com/terms)
- Hailuo web terms: not retrieved (gap).
- Gemini API terms prohibit using the services to build competing models and reverse engineering/replicating components including weights. — [Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms)

### Inferences
- Kling's 3.1(h) and 3.1(g) make any script or app that drives the consumer Kling web UI a clear violation; its official API is a different agreement (not retrieved).
- Google's Flow credits are a consumer-app benefit; no source suggests a sanctioned way to spend them from third-party code. Introcut should keep the project's existing stance: never claim Flow credits can be spent.
- The Kling clause 4.5/4.6 and the Google "AI-generated" disclosure expectation fit the project's rule to show an "AI-generated" reminder at export and never remove watermarks (SynthID on Gemini outputs is described as always on).

### Gaps
- Full Flow/Google Labs additional terms, Generative AI Prohibited Use Policy text, Hailuo/MiniMax consumer terms, Kling API developer agreement.

## 6. Practical orchestration patterns

### Takeaway
Every route is async: submit, get a job/prediction ID, poll (or webhook), download. Reference images and start/end frames are supported by the Google, Runway and Luma routes in the retrieved docs, which is how to keep a character consistent across clips; draft cheaply at low resolution, then regenerate only approved shots.

### Cited Findings
- Gemini Omni: poll file state to `ACTIVE` before download (`FAILED` = failed); `delivery="uri"` for videos over 4 MB; image-to-video, first/last frame, multi-image subject reference, multi-turn editing; 360p/720p tiers allow cheap drafts; extension in 3-10 s chunks. — [Gemini Omni docs](https://ai.google.dev/gemini-api/docs/omni)
- Replicate: async by default, webhooks with event filters, or poll every 1-2 s. — [Replicate](https://replicate.com/docs/topics/predictions/create-a-prediction)
- fal: queueing when over concurrency (starts at 2 concurrent, up to 40 with spend). — [fal FAQ](https://fal.ai/docs/model-apis/faq)
- Billing only on success: Gemini pricing page says you are charged only if the video is generated successfully; a Pika source says only successful runs are charged. — [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing); [APIFrame Pika](https://apiframe.ai/guides/pika-labs-api-guide) (secondary)
- Luma Ray3.2 has a large price gap by resolution (540p $0.15 vs 1080p $1.20 for a 5 s clip), which makes draft-then-upgrade worthwhile. — [Luma API pricing](https://lumalabs.ai/api/pricing)
- A forum report (Gemini API) says the AI Studio UI displayed Veo 3.1 Lite as a per-video label while charges were per second ("costs 8 times more"). — [Google AI forum](https://discuss.ai.google.dev/t/veo-3-1-lite-pricing-shows-0-05-per-video-but-actually-costs-8-times-more/143844)

### Inferences
- Pipeline suggestion: (1) generate a keyframe still per shot, (2) image-to-video at 360p/540p/720p draft, (3) user approves, (4) re-render approved shots at final resolution with the same seed/prompt/reference images; cache by hash of (provider, model, prompt, reference images, params) and never re-submit identical jobs.
- Persist job IDs in the project JSON so a closed tab can resume polling; show a cost estimate (seconds x price) before each submit; set a per-project spend cap.
- Retries: charged per success, but a clip may be unusable; plan 1.5x generation as a budget default.
- Provider outputs expire (Gemini historically about 2 days: verify), so download and store in OPFS immediately.

### Gaps
- Seed/determinism support, webhooks for Gemini/Runway/Luma/Kling, and retention windows not verified.

## 8. Recommendation (zero developer cost)

### Takeaway
Support a small number of user-supplied-key integrations behind one "generator profile" interface, start with Gemini Omni Flash, fal.ai (gives Kling, Seedance, MiniMax with one key) and optionally Runway/Luma; make everything else "recommend + copy prompt + import clip". Do not support Sora, scraping, UI automation, or Colab/Kaggle remote driving.

### Cited Findings
Bring-your-own-key candidates, with the reasons found above:
1. Google Gemini API, `gemini-omni-1.1-flash`: official, 9:16, audio, frame/subject references, async; note: no free tier, keys should not be shipped in client code, and unrestricted keys are being phased out. — [Pricing](https://ai.google.dev/gemini-api/docs/pricing); [Omni docs](https://ai.google.dev/gemini-api/docs/omni); [API keys](https://ai.google.dev/gemini-api/docs/api-key)
2. fal.ai: one key for many video models; FAQ confirms browser calls are possible but keys should be proxied. — [fal FAQ](https://fal.ai/docs/model-apis/faq)
3. Runway and Luma: simple per-second / per-clip pricing in primary docs. — [Runway](https://docs.dev.runwayml.com/guides/pricing/); [Luma](https://lumalabs.ai/api/pricing)

### Inferences
- **BYOK (V1 or V1.5):** Gemini Omni Flash; fal.ai (Kling v3 / Seedance / MiniMax); Runway; Luma. Later: Replicate, Kling official, BytePlus, DashScope Wan, xAI, Pika (after verifying pricing/CORS/terms). Each needs a browser CORS test; if CORS fails, fall back to "paste output URL / upload downloaded clip".
- **Recommend and copy prompt (manual):** Google Flow (Veo, user's own credits), Kling web, Hailuo web, Pika/Grok web, HF Spaces opened by the user. Introcut generates shot prompts, shot-by-shot start frames and file-naming instructions, then imports the downloaded clips.
- **Optional, clearly labelled opt-in:** the user's own Hugging Face Space (already allowed by the project rules) for open-weights video such as Wan 2.2 5B; user runs their own notebook (Colab/Kaggle) manually with a provided notebook link, with no remote driving.
- **Do not support:** OpenAI Sora API (shut down); scraping or automating Flow/Kling/Hailuo/Pika web UIs (Kling 3.1(h) explicit; Google ToS automated access clause); using Flow credits through the API (not supported); watermark removal (SynthID/Kling labelling); remote-controlling Colab (FAQ restrictions); the retired `veo-3.1-*` model IDs.
- Caveat: shipping the developer's own key would break the zero-cost rule; keys must stay in the user's browser (local only), and the UI must warn about cost per submission and spend caps.

### Gaps
- Real CORS tests, an official-terms check for Kling/BytePlus/MiniMax/Alibaba API agreements, and confirmation of Cloud trial credit use for Omni Flash should be completed before implementation.
