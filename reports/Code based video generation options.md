# Code Can Build Introcut's 30-Second Shorts

**Yes, you can generate video "through code", people already do it at scale, and Introcut can do most of it at zero cost, but not the ZackD.Films 3D-cartoon look.** The phrase covers three different things. (1) Code that renders motion graphics is mature: Remotion has 66k GitHub stars, HeyGen's Apache-2.0 HyperFrames has 69k, and Introcut's own plan (Canvas renderer, JSON project, Mediabunny export) is already this approach. (2) An AI that writes that code or a scene spec went mainstream in 2026: Anthropic shipped Claude Motion in beta (launch date 8 Oct 2026 per a third-party summary) and says it uses no video model. It works well for text, numbers, charts, UI mockups and captions and fails for people, faces and organic motion. (3) AI video models called through APIs work, but nothing is free: the cheapest credible route is about **$0.10 per second**, so a 30 s story costs **$3 raw and about $4.50 with retries**, and Google Flow credits cannot be spent through the API. The default recommendation is to make Introcut work with **zero generated clips** first. It would build stories from the user's stills (or Introcut-rendered text and number scenes) with camera motion, voice and captions, then treat generated clips as optional "hero shots" from the free tools or, later, from the user's own API key. That reverses the current assumption that users must generate clips by hand. The first milestone is a thin end-to-end slice (scene templates, stills, English voice, captions, MP4 export, benchmarked in Chrome), because nobody has yet shown that Introcut's pipeline can produce a finished file. The weakest link is Nepali voice, which has no proven free option. The biggest external risk is YouTube's rule against templated, mass-produced content.

## Three meanings, three maturity levels

**Meaning 1, code that renders motion, is established and mostly license-blocked or server-bound for Introcut.** Remotion (React to video) has [66,130 stars](https://api.github.com/repos/remotion-dev/remotion) but a custom license that CLAUDE.md already rules out ([LICENSE.md](https://raw.githubusercontent.com/remotion-dev/remotion/HEAD/LICENSE.md)). HyperFrames is [Apache-2.0](https://api.github.com/repos/heygen-com/hyperframes), but it needs Node, FFmpeg and headless Chrome to export ([README](https://github.com/heygen-com/hyperframes)). Revideo and Motion Canvas are MIT but also render on Node with a headless browser ([Revideo](https://github.com/redotvideo/revideo)). Manim is MIT but Python. Only two tools have a documented browser-only MP4 path, Remotion's web renderer and the small Apache-2.0 VideoFlow, and **both encode through Mediabunny and WebCodecs**, the same stack Introcut already chose ([VideoFlow](https://github.com/ybouane/VideoFlow), [Remotion web renderer](https://www.remotion.dev/docs/web-renderer)). The practical reading is that Introcut does not need to adopt any of these engines. It already owns the hard parts, a deterministic `renderFrame` plus WebCodecs export, and can borrow ideas (VideoFlow's renderer-agnostic `VideoJSON`) without taking dependencies. Diffusion Studio is excluded because removing its watermark needs a paid key ([README](https://github.com/diffusionstudio/core)); Etro is GPL-3.0 ([API](https://api.github.com/repos/etro-js/etro)).

**Meaning 2, AI that writes the code or spec, is real and now productised, but the reliability evidence is thin and mostly from Manim.** Claude Motion's [help article](https://support.claude.com/en/articles/17454997-get-started-with-claude-motion.md) describes Claude writing code that animates text, charts, shapes and images, with no video generation model, in beta on Team and Enterprise plans. Remotion ships [agent skills](https://raw.githubusercontent.com/remotion-dev/skills/main/README.md) and a [prompt-to-motion-graphics template](https://raw.githubusercontent.com/remotion-dev/remotion/main/packages/template-prompt-to-motion-graphics/README.md). HyperFrames ships 7 agent skills and about 450 prebuilt blocks. Hera (YC S25) and Jitter sell prompt-to-motion tools. One-shot code generation fails often: in a Manim benchmark, success with zero retries was 0 to 7% across models, but **5 attempts reached 91 to 96%** ([TheoremExplainAgent](https://arxiv.org/html/2502.19400v2)). The bigger problem is output that renders but looks wrong. HeyGen's benchmark lists overlapping text mid-animation, elements drifting off-frame and abrupt linear motion ([HeyGen](https://www.heygen.com/research/introducing-code2video-benchmark), vendor-run). The strongest design lesson is that a planning stage matters most: removing the planner cut aesthetic scores from 79.0 to 38.1 in one study ([Code2Video](https://arxiv.org/html/2510.01174)). I found no head-to-head test of a constrained JSON spec against free-form code. The industry pattern of trusted components plus model-filled content (HyperFrames blocks, Remotion's constants-first template, Shotstack and Creatomate JSON) points the same way. For Introcut this is a gift: the LLM fills a Zod-validated JSON through ops, so invalid code cannot run, locks and undo keep working, and no sandbox is needed. A small in-browser model's success at filling templates is untested, so it needs a spike.

**Meaning 3, AI video models through APIs, is the only one that makes photoreal or organic footage, and it is paid.** Google is mid-migration: all Veo 3.1 preview models are listed as shutting down on 22 Oct 2026 (today), replaced by `gemini-omni-1.1-flash`, which has no free tier and supports 9:16, native audio, image-to-video and first/last-frame control ([pricing](https://ai.google.dev/gemini-api/docs/pricing), [Omni docs](https://ai.google.dev/gemini-api/docs/omni)). OpenAI's Sora API was switched off on 24 Sep 2026 per secondary reporting ([The Decoder](https://the-decoder.com/openai-sets-two-stage-sora-shutdown-with-app-closing-april-2026-and-api-following-in-september/)). Model names change every few months, so provider and model IDs must be data, not code.

## What each approach can and cannot make

Code-rendered video is strong where pixel models are weakest. In the Code2Video study pixel video models scored near zero on text-heavy explainers because of blurry, corrupted text and inconsistent style, while code methods won clearly ([Code2Video](https://arxiv.org/html/2510.01174)). The workable list for Introcut is kinetic typography, captions, big-number reveals, charts, chat and phone mockups (including the user's own screenshots), diagrams, timelines and motion over still images. Code cannot yet give photoreal people, faces, hair, cloth or rigged 3D characters. Remotion's and HyperFrames' own examples stop at motion graphics, and I found no evidence of a quality character pipeline in Three.js or Blender-by-LLM ([BlenderMCP example](https://glama.ai/mcp/servers/@ahujasid/blender-mcp/blob/7636d13bded82eca58eb93c3f4cd8708dfdfbe8b/README.md) is a low-poly scene).

**A ZackD.Films-like look is therefore not achievable by code alone.** I could not find ZackD's real pipeline. Low-authority copycat tutorials describe AI image tools for scenes and an image-to-video tool (Grok) to animate each one, then CapCut to assemble, and one marks the channel at 24M+ subscribers, which is an unverified marketing claim ([Lilys summary](https://lilys.ai/en/notes/ai-shorts-20251110/make-zack-d-style-ai-shorts-free)). Taking that at face value, the look comes from generated stylised images plus generated motion. The achievable code-only substitute is a "motion comic": consistent stylised stills, Canvas push-ins and pans, optional depth parallax, grain, shake, hard cuts, sound design and kinetic captions. It will look visibly lower-motion than the real thing (my inference). The bridge is the hybrid: a few real image-to-video clips at the hook, twist and ending, and code motion in between. Depth parallax is possible with Depth Anything V2 Small (Apache-2.0; the larger sizes are non-commercial), but the only mature parallax tool, DepthFlow, is AGPL and Python, so Introcut would write its own shader ([Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2), [DepthFlow](https://github.com/BrokenSource/DepthFlow)). No data compares viewer reaction to Ken Burns, parallax and full AI motion.

## Real costs, free routes and what a browser can export

| Route | Price | 30 s raw | Free quota |
|---|---|---|---|
| Gemini Omni Flash, 720p with audio ([Google](https://ai.google.dev/gemini-api/docs/pricing)) | about $0.10/s | $3.00 | none |
| Runway gen4_turbo ([Runway](https://docs.dev.runwayml.com/guides/pricing/)) | $0.05/s | $1.50 | none found |
| Luma Ray3.2, 720p, 5 s clips ([Luma](https://lumalabs.ai/api/pricing)) | $0.30 per 5 s | $1.80 | none found |
| Kling V3 on fal ([fal](https://fal.ai/pricing)) | $0.14/s | $4.20 | unknown |
| Seedance 2.0 via BytePlus (secondary; [Kingy.ai](https://kingy.ai/ai/byteplus-review-seedance-2-0-turns-byteplus-into-a-serious-ai-video-platform/)) | about $0.76 per 5 s | $4.56 | unknown |
| Wan 2.2 5B open weights, own 24 GB GPU ([model card](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B)) | electricity | $0 | n/a, about 9 min per 5 s clip |

Plan for 1.5x retries, so the realistic good-quality budget is **$4.50 to $7 per story**. There is no free video API. Hugging Face ZeroGPU gives free accounts about 5 GPU-minutes per day, enough for one or two clips ([HF docs](https://huggingface.co/docs/hub/spaces-zerogpu)). Flow credits belong to the consumer app, and a Google forum reply says AI Pro is limited to web apps and excludes API requests ([forum](https://discuss.ai.google.dev/t/does-google-one-ai-pro-include-api-access-for-veo-3-or-is-it-limited-to-flow-only/110794)). The only plausible "free" budget is Google Cloud's $300 trial, secondary-sourced and not confirmed for Omni (at $0.10/s that would be about 3,000 s, in theory). Driving someone's Colab remotely is restricted by Colab's FAQ ([Colab FAQ](https://research.google.com/colaboratory/faq.html)), and Kling's policy forbids "automated scripts" against its service ([Kling policy](https://kling.ai/docs/user-policy)). The compliant pattern is a user-supplied key behind one `submit, poll, download` interface. Whether fal, Replicate or Google allow direct browser calls (CORS) is untested, and Google's docs say not to ship keys in client code ([API keys](https://ai.google.dev/gemini-api/docs/api-key)).

**Browser rendering and export are feasible with caveats.** WebCodecs is in Chrome and Edge 94, Firefox 130 and Safari 26, about 95.5% of global usage ([caniuse](https://caniuse.com/webcodecs)). Mediabunny's `CanvasSource` turns a canvas into an MP4 track with backpressure, and `StreamTarget` writes to disk instead of holding the file in RAM ([guide](https://mediabunny.dev/guide/writing-media-files)). The caveats are device-specific: AAC encoding is not guaranteed in every browser, so Introcut needs a runtime check and the `@mediabunny/aac-encoder` fallback, whose license is unverified ([Mediabunny](https://mediabunny.dev/guide/supported-formats-and-codecs)). A 1080p30 H.264 encode table shows **11 fps on a low-end Windows netbook and 200 fps on a MacBook M4**, with no stated methodology ([webcodecsfundamentals](https://webcodecsfundamentals.org/basics/encoder/)). A 900-frame export is therefore anywhere from about 5 seconds to 80 seconds of encoding, plus render cost. My unmeasured guess is 1 to 3 minutes typical, so Introcut must publish its own benchmark. The encoder queue must be bounded and frames closed, or memory runs out. iPhone HEVC clips decode only where the OS supports HEVC ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API)). Devanagari rendering in Canvas, bundled-font loading and emoji consistency are all untested; the safe rules are to bundle an OFL font and split captions per word, never per code point. Phones are not a V1 target.

## The faceless stills-and-voice route works, and Nepali voice is its weak point

Stills with code motion, voice-over and captions is the one pipeline that runs fully in the browser at zero cost to Introcut, and open-source repos prove the idea but not the stack. MoneyPrinterTurbo ([134k stars, MIT](https://api.github.com/repos/harry0703/MoneyPrinterTurbo)) and ShortGPT automate script, stock footage, TTS and subtitles, but server-side with Python and FFmpeg, and neither animates code or runs in a browser. Introcut's differentiator is browser-only, user-owned assets and stylised stills.

Stills are the awkward input at zero cost. The Gemini API has **no free tier for any image model** ([pricing](https://ai.google.dev/gemini-api/docs/pricing)). FLUX.1 schnell is Apache-2.0 but only reachable through paid or tiny-credit hosts ([model card](https://huggingface.co/black-forest-labs/FLUX.1-schnell)). In-browser SD-Turbo exists on WebGPU but is a hardware-dependent experiment ([ONNX Runtime Web](https://opensource.microsoft.com/blog/2024/02/29/onnx-runtime-web-unleashes-generative-ai-in-the-browser-using-webgpu/)). So the cleanest approach is that the user generates stills in free tools they already use, and Introcut supplies a prompt pack with a character-sheet reference and a fixed style block. Character consistency across 6 to 12 stills is imperfect; sources are anecdotal, so hide drift with stylisation, cuts and partial views rather than promise it.

For voice, English is solved and Hindi is probable. Kokoro is Apache-2.0, runs in the browser and lists Hindi, but a community page grades its Hindi voice only "C" on data quality, so Introcut must run its own listening test ([Kokoro](https://github.com/hexgrad/kokoro), [Replicate readme](https://replicate.com/codingayam/kokoro-82m-complete/readme)). **Nepali is not in Kokoro and has no proven free option.** Gemini TTS lists Nepali and Hindi and is marked free through a user's API key, but Google may use free-tier content to improve products and humans may review it, so it needs an on-screen opt-in notice ([speech docs](https://ai.google.dev/gemini-api/docs/speech-generation), [terms](https://ai.google.dev/gemini-api/terms)). Offline community models (Kala, Matcha-TTS Nepali) are young; one reports a Whisper character error rate around 0.41 to 0.44 and neither has a listening test, and their weights are CC-BY-SA or CC-BY, which need a license read before bundling ([Matcha-TTS Nepali](https://huggingface.co/sandipghimire/matcha-tts-nepali), [Kala](https://pypi.org/project/kala-tts/)). Indic Parler-TTS (Apache-2.0) scored about 64% with Nepali native speakers pretrained and about 80% fine-tuned, but at 0.9B parameters it is too heavy for the browser ([model card](https://huggingface.co/ai4bharat/indic-parler-tts)). Meta MMS is non-commercial, and Edge voices rely on an unofficial endpoint. The honest Nepali ladder is: the user's recorded voice (always works), Gemini TTS via the user's key, then an offline beta voice labelled as such. Because Introcut writes the script, captions can come from aligning known text to audio rather than transcribing Nepali, but that approach is untested (Whisper word timestamps on WebGPU had an open limitation ([issue](https://github.com/huggingface/transformers.js/issues/820))).

## Platform and legal risk centres on sameness, disclosure and clip licenses

The sharpest risk is not "AI" but templating. YouTube's monetisation policy lists as ineligible "image slideshows, templated storylines" and "AI-generated content made with generic or unoriginal templates giving the impression of mass production", while allowing recurring formats where each video has its own storyline ([YouTube policy](https://support.google.com/youtube/answer/1311392), read through a summariser, so re-read before quoting). A product that stamps one template across a channel is the exact pattern at risk. Press reports a January 2026 sweep of large AI-slop channels, with vendor-sourced figures ([Tubefilter](https://tubefilter.com/2026/01/29/youtube-ai-slop-channel-crackdown-bans/)). Independent data on legitimate faceless channels being hit is absent.

Disclosure is required and automated. YouTube asks creators to toggle "AI use" for realistic synthetic content, exempts clearly non-realistic or animated content, scripts and cloning your own voice, and says labels do not affect monetisation ([YouTube](https://support.google.com/youtube/answer/14328491)). From 27 May 2026 it auto-labels significant photorealistic AI, with an overlay on Shorts ([TechCrunch](https://techcrunch.com/2026/05/27/youtube-will-now-automatically-label-ai-videos/)). TikTok requires labels for realistic AI content and bans automation designed to bypass its systems ([TikTok guidelines](https://www.tiktok.com/community-guidelines/en/integrity-authenticity)). Instagram's AI-generated profile label applies to accounts featuring an AI-generated person, so it matters for the avatar feature, not for faceless output ([MediaPost](https://mediapost.com/publications/article/417580/instagram-limits-reach-for-creator-profiles-withou.html)). Imported Google clips carry SynthID and C2PA; Google added a visible-badge toggle on 14 Aug 2026, but not in countries requiring visible marks, and creators in India report seeing it ([Search Engine Journal](https://searchenginejournal.com/google-lets-you-turn-off-visible-watermarks-in-gemini/586145)). Introcut should preserve credentials where it can and never crop or strip marks. India's IT Rules amendments (effective 20 Feb 2026) require labelling of synthetic media and put the main duty on platforms, with further tightening only proposed ([Hogan Lovells](https://www.hlc.com/en/publications/india-introduces-mandatory-labelling-for-ai-and-3hour-takedown-for-illegal-content), [Mondaq](https://www.mondaq.com/india/new-technology/1801930/india-tightens-oversight-on-ai-generated-content-under-it-rules)). Nepal has no AI-specific copyright or labelling provision that I could find, and no statute text was read, so a local lawyer should confirm ([NepJOL](https://nepjol.info/index.php/fwje/article/view/83288)).

Ownership is the second exposure. The US Copyright Office says prompts alone do not make a user the author of AI output, while human selection, arrangement and edits can be protected ([IPWatchdog](https://ipwatchdog.com/2025/01/29/part-two-copyright-office-ai-report-says-creative-prompting-doesnt-constitute-authorship/)). Blogs report Kling free-tier output as non-commercial; this is unconfirmed from official terms, and I could not read Flow's output terms at all. So the unresolved licensing risk sits with imported free-tier clips, which argues for asking users to confirm commercial rights per clip. For music, Pixabay's license forbids redistributing files standalone, so bundling it in an open repo is unsafe; use CC0 sources or user music ([Pixabay](https://pixabay.com/en/service/license/)).

## Recommendation: build a code-native story engine first, add clips later

The default is a **spec-first hybrid**. Introcut's LLM (basic rules, WebLLM or the user's key) fills validated JSON scenes. Introcut's own Canvas engine renders them: native templates for text, numbers, charts, mockups and captions; user stills with camera motion; and generated clips only for hero beats. The order below follows risk and cost.

| Order | What | Why |
|---|---|---|
| 1 | Scene templates (about 15 to 25, each a Zod props schema plus a pure render function with easing and safe-area layout), stills with camera moves, English Kokoro voice, captions, MP4 export | Zero cost, fully in-browser, works with no generated clips, and tests the export risk early |
| 2 | Voice tiers and gates: own recording, Gemini TTS via user key, offline Nepali beta, Hindi listening test, script-to-audio alignment | Nepali is the weakest, riskiest link and a core language promise |
| 3 | Disclosure and variety guard in the export flow: per-project AI-use card, rights checklist, similarity warning across recent exports | Matches the YouTube, TikTok and India rules and keeps users off the "templated" side |
| 4 | Optional bring-your-own-key clip generators behind one interface, starting with Gemini Omni Flash and fal (Kling, Seedance), with cost preview, spend cap and a 540p to 720p draft before final | Higher fidelity and the closest route to the ZackD feel, but paid, so strictly opt-in |
| 5 | Later: depth parallax, Lottie overlays, a sandboxed code escape hatch | Nice-to-have; free-form LLM code is costly, unreliable and needs a sandbox |

**This changes the current plan in four ways.** First, clips stop being a prerequisite: today the product assumes users generate clips by hand in Flow, which at roughly 50 daily credits (secondary-sourced) is slow and cannot carry a 30 s story. Clips become optional hero shots, and "stills plus voice" becomes a first-class input type with a prompt pack for the free image tools. Second, the generator registry (M4) becomes two things: free-tool prompt packs and a BYOK profile interface carrying price, duration, aspect ratio and license as data. Third, export (M12) should be pulled forward as a thin slice, because the plan produces no finished video until then and every claim about speed and memory depends on it. Fourth, the gate list needs new entries: export benchmark, Devanagari canvas test, Nepali listening test, BYOK CORS test, and a spike measuring how often a small local model emits schema-valid scenes. G1 (does Veo speak clear Nepali) matters less, and the Veo 3.1 shutdown shows model names will keep moving. Do not adopt Remotion, HyperFrames or Revideo, do not run LLM-written code in V1, and do not support Sora, UI automation, Colab remote driving or any watermark removal.

**The first milestone is "M-Slice: one story, end to end."** Build three or four scene templates (hook text, big number, still-with-camera, caption layer), a six-beat fixture project, `renderFrame` shared by preview and export, English Kokoro voice with word captions, and a Mediabunny export to a 1080x1920, 30 fps MP4 using `StreamTarget`. Acceptance means the following. The exported file matches the preview frame for frame. A 30 s export finishes with a progress bar and a measured time on at least two machines (one low-end), with the number published. The AAC check and fallback work. A Devanagari test string ("क्ष त्र ज्ञ श्री", plus a matra such as "कि") renders correctly in the bundled font. Memory stays bounded. If this slice fails on a mid-range laptop, the whole browser-only premise needs rethinking before more features are built, which is why it comes first.

## Conclusion

The notes change the question. "Can Introcut generate video?" is the wrong frame, because the cheapest and most reliable way to make a video is to not generate pixels at all. Code-native scenes and AI-filled specs already cover the content types that pixel models get wrong (text, numbers, interfaces), and Introcut's existing JSON, ops and locks architecture is the safe version of what Claude Motion and HyperFrames do with free-form code. The clips the original plan leaned on are the expensive, licence-uncertain and policy-exposed part, and they work best as a small garnish rather than the meal.

What remains unproven is where the risk concentrates. Nobody has measured Introcut-style browser export on low-end hardware, Nepali voice quality, a small local model's ability to fill templates, or whether motion-comic stories hold viewers; the audience-data gap applies to every route here. Platform policy cuts against volume and sameness, so the product's survival with creators depends on built-in variety and disclosure, not on the renderer. These are testable in weeks, which is why a thin end-to-end slice, not more planning, is the next step.
